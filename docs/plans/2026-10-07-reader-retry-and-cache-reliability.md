# 阅读重试、上下翻页与缓存可靠性修复

用户已授权实现。目标是消除已复现的客户端错误：重试回旧章、过期请求覆盖新章、
缓存目录在新 runtime 中缺少正文边界，以及兼容源 HTTP 错误丢失结构化状态。
站点持续拒绝访问时，应保留可重试的失败状态和最后成功进度；不能保证上游一定提供正文。

## 范围与分工

- reader：`lib/pages/reader/book_source/` 的加载、重试、连续滚动和进度保存；
  复用已有 load serial/catalog generation/recovery，不另建并行导航层。
- ReadingSource：backend、runtime 会话与 HTTP 错误边界；只在未缓存正文确需 runtime 时
  恢复依赖状态，保持已有离线正文复用；修复后失效旧语义下生成的正文缓存。
- 测试：受控 source/backend、独立 reader widget 文件；修复已有垂直恢复验证超时的实际原因，
  保留断言，不用 skip、超长超时或来源特例掩盖失败。
- 文档：本计划、诊断记录和本次验证记录。不改版本、不发布、不修改用户提供的书源。

## 修改前的行为锁

1. 将 HEAD 已复现的“第 2 章失败，网络恢复，Retry 仍显示第 1 章”改为正式正确行为断言。
2. 覆盖上下翻页的逐章/整书分支、失败后重复重试、退出重开、迟到响应。
3. 将冷 runtime + 磁盘目录 + 未缓存正文跨章/尾 404 诊断改为正式回归。
4. 保留原分页、缓存重开、离线正文、403 不无限刷新、一次缺章恢复行为。

## 清理与修复顺序

1. 失败目标、可见章节和保存进度一致；旧 load 无权提交状态。
2. 找出并修复当前工作区垂直阅读恢复测试不结束的根因。
3. 将 cache 命中与 runtime 初始化拆开；补齐正文依赖状态、HTTP status 和有界恢复。
4. 复用既有缓存/恢复机制，删除修复范围内重复的旁路；不加依赖、不写书源名称或地址分支。
5. 分文件隔离运行定向回归，格式化和静态分析；审阅本次增量，记录真实设备/上游限制。

## fallback 分类

- 失败后退回上一章：掩盖失败目标，修复。
- 冷缓存目录冒充 runtime 已初始化：破坏正文边界，修复。
- 缺失章节只刷新一次：有依据的外部状态恢复，保留并覆盖二次失败。
- 后台邻章预取失败暂不提示：有界、可在前台重试，保留错误到前台且禁止污染进度。
- 离线已缓存正文复用：保留；不能为恢复运行状态而强制联网读取已有正文。
- HTTP 403：明确失败，保留状态；不通过无限刷新或降低断言绕过网站拒绝。

## 完成标准

定向回归证明失败目标正确、过期请求不落地、垂直恢复可结束、目录冷缓存不串章、
已缓存正文离线可读、缺章恢复有界且 403 不伪装成功。静态分析无本次引入的问题。
本次不把本地测试通过宣称为用户设备或所有书源已验证。
