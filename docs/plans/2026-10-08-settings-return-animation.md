# 设置返回动画的调查与清理计划

## 范围与保留行为

从真实设置首页打开偏好设置并返回；检查共享路由转场、首页通知边界、
共享子页系统栏。保留毛玻璃强度、渐变曲线、页面布局、标准 iOS 返回手势、
取消手势、主题/语言/权限的即时更新、阅读器自有转场与用户数据。
不增加依赖，不修改其他功能的未提交改动。

## 已见证据与待验证假说

- 分类入口使用 MaterialPageRoute；iOS 默认 Cupertino 转场保留实时页面，
  不调用阅读器自定义动画。不能声称整个偏好页每帧重建。
- 上下两页包含 GradientTopBackdrop，原生 shader blur 要在背景变化时合成。
  返回同时滑动两层页面，是否是主要开销须用原生 Profile 帧时间确认。
- 首页 didChangeDependencies 全量 watch AppSettingsNotifier，绕过 build 中
  的局部 select；路由状态变化也触发整壳依赖更新和重复系统栏调用。
- 子页系统栏同时在 didChangeDependencies 和每次 build 的 postframe 写入；
  需要保留返回恢复行为，消除重复/无关写入。

## 清理次序

1. 跑现有设置工作量、子页和首页系统栏回归；补 route/系统栏通知计数验证。
2. 建立原生 Profile 诊断：调用原应用入口，选中“我的”，反复打开真实偏好
   页并返回，分别记录 UI 与 raster 的 p50/p90/max 和超预算帧。不得把
   widget 测试、安装成功或离屏耗时当作真机 FPS。
3. 根据测量选择最小修复。优先复用现有 Provider、AnnotatedRegion、标准
   Cupertino 路由和 Flutter SnapshotWidget；架构变化先独立只读审查。
   快照只用于返回、尊重 route optout/平台视图/Web 边界，推入保持实时。
   若首帧快照增加卡顿或画面不等价，放弃该方向。
4. 删除重复系统栏工作和全量首页订阅，逐项补回归并跑独立测试进程。
5. 同条件重复 Profile 测量，记录首帧与稳定帧；完整静态检查、iOS 构建，
   在 SloanePro 原位安装正常应用并核对包身份/启动。

## 兼容与风险

Gaussian 的旧渲染后端分带路径、液态玻璃的平台视图/不支持 shader 回退
均为已知渲染边界，本次保留。无证据支持的静默异常、删功能、降模糊强度、
延迟用户设置写入与跳过测试均不可作为优化。
快照可能冻结动画/异步数据，因此只允许短暂返回阶段且结束/取消必须释放；
图片/内存开销和首帧成本需要实测。最终报告区分自动测量和用户实体观感。

## 执行决策与进度

独立架构与代码审查支持定向清理，不替换全局主题或引入新控制器。
真机 clean baseline 确认返回第二帧 raster 超预算；局部双页 Snapshot 实验
虽降低 raster 稳定耗时，却让 UI 最高达 20.670ms，已完整撤销。
最终保留标准 MaterialPageRoute、共享系统栏恢复、首页按值订阅和 131 行
死路由删除。CPU/平台工作量回归通过；raster 起始峰值仍需 GPU trace。
