## 文档维护规则

- 功能或架构改动完成前，同步更新对应当前说明中的调用链、所有权、失效条件、源码位置、回归入口和已知限制。
- 每个主题保留一个当前维护入口。概览和验收记录链接到它，不另复制完整实现说明。
- 完成计划中已被当前说明和验收覆盖的任务清单及时删除，更新所有引用；不保留“已完成但仍待执行”的重复步骤。历史内容可从 Git 或已有归档快照找回。
- 有独立价值的诊断、设计取舍、测试、迁移和发布证据保留日期，明确历史状态并链接当前说明。阶段性失败不能写成当前缺陷，旧成功结果也不能写成当前验证。
- 删除前搜索引用并核对是否包含唯一证据。仍在执行的计划、其他话题的未完成工作和用户维护的文件，不按日期直接删除。
- 临时日志、源码摘要和签名包放在忽略的 `build/` 下；文档记录结果及收据位置，不复制凭据、数据库或整段工具输出。
- 结束前检查文档链接、源码/测试路径和 diff。仅修改文档时不触发应用构建或真机安装。
