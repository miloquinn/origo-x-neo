# 2.7.2 / 260927002 — Origo code redemption

## Product change

- Profile cards use Explore naming, show Read included for active Explore
  accounts, and use coordinated card colors instead of a detached white row.
  Membership status/trial/settings copy is consistent across ten locales.

- The user explicitly selected self-generated Origo codes after the distinction
  from official store codes and review risk was explained. No pending code-type
  decision remains.
- Signed-in Google Play and Apple users see “I have a code” on Explore, including
  Apple beta. The secondary page shows the destination account, calls the same
  backend as the direct channel, and applies server-returned membership.
- No shop link, shop branding, new dependency, duplicated billing system or
  review-specific hiding. Native purchase and restore remain available.
- Input is trimmed; blank/double submission is prevented; failure preserves the
  code and account switching clears it. Redemption success is no longer masked
  by a later supplementary referral refresh failure.
- Ten locales use generic redemption labels, without incorrectly promising
  every code grants permanent rights. Existing direct-channel layout remains.
- Build 260927001 already distributed does not contain this new entry.
