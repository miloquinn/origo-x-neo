# 登录与账户界面设计

状态：**用户已批准，正式 Flutter 页面已接入，2026-09-26**。本轮修改登录、注册、账户、资料、安全、权益与邀请界面，认证沿用现有账户 API。后续独立应用/高级版变更见下方渠道规则及独立商品方案。截图使用测试账户。当前工作区已生成 Android 调试包，未上传新商店版本；已送审包不会随本地修改自动更新。

## 设计判断

现状最影响体验的是认证流程的纵向叠加：介绍卡、表单卡、注册的五个字段、第三方登录和说明都处于同一条长列表。已登录账户已有资料、安全等二级页面，因此保留这些路径，统一呈现方式即可。会员页面把购买和恢复放在多段权益说明之后，也需要调整顺序。

改版前证据来自 `account_page.dart` 中的整页 ListView、注册字段和各模式共同追加的第三方区域，以及 `premium_membership_page.dart` 中权益说明先于购买的顺序。资料、安全、MFA、换邮箱、注销等功能已有实现，不另造业务体系。

## 核心规则

- 一屏一个任务。普通 390×844 手机、默认字号和键盘收起时，认证每一步及账户首页能看完整个主要操作区。
- 内容按功能分层，不以更多折叠卡代替清晰导航。密码/验证码阶段不再重复品牌介绍或第三方登录区。
- 不禁止滚动。320px 小屏、130% 字号、横屏、键盘打开时，表单自然滚动，焦点字段与提交按钮可达；不缩字、不裁掉错误或强行固定高度。
- 整页浅色表面、24px 表单边距、16px 字段圆角、52px 主按钮、紧凑设置行。账户列表用轻填充分组，不套多层描边卡片。
- 继续使用 App 的主题色、字体、品牌图标、深浅色和共享子页顶栏。原型用标准 AppBar 展示信息布局；正式接入使用 `FloatingSubpageScaffold`，不另建导航风格。

## 页面与流程

| 页面 | 首屏内容 | 去向 |
| --- | --- | --- |
| 登录入口 | 小品牌图标、标题、邮箱、继续、创建账户、主要第三方按钮 | 邮箱密码页 / 注册 / 其他方式面板 |
| 邮箱密码 | 邮箱摘要、密码、登录、找回密码、验证码登录 | 成功后回原任务；如需 MFA 先验证 |
| 注册 1/3 | 邮箱、发送验证码 | 输入验证码 |
| 注册 2/3 | 邮箱、验证码、重发倒计时 | 设置账户；仅收集验证码，不提前显示“验证成功” |
| 注册 3/3 | 用户名、密码、确认密码 | 注册提交；昵称与头像留给资料页 |
| 找回密码 | 邮箱、发送验证码 | 验证码、新密码、确认密码，沿用 API 成功后登录的行为 |
| 外部授权 | 在浏览器继续、重新打开、取消 | 回调自动返回；过期后重试 |
| MFA 登录 | 验证器代码、确认、退出当前挑战 | 成功后回原任务 |
| 账户 | 紧凑身份卡、资料/安全/账号与权益；官网版还有邀请好友 | 二级页；退出登录需确认 |
| 个人资料 | 头像、昵称、用户名、保存 | 头像仍用现有选择/裁剪/删除流程 |
| 账户与安全 | 邮箱、密码、两步验证、已绑定登录方式 | 各自任务页；注销保持单独入口与现有风险确认 |
| 我的权益 | 当前状态、价格、购买/试用/恢复、两项简短权益 | 细则按需打开 |
| 邀请好友（官网版） | 邀请码、分享、简短统计 | 邀请记录、规则、绑定邀请码分别进入 |

邮箱先输入的路径保持现状，不增加查询邮箱是否存在的接口。注册后端要求 username、password、challenge、code，display_name 为可选（`origo-x-platform/app/routes/account.py:87`）；分步只改变采集顺序，最终仍一次调用现有注册 API。验证码失败返回验证码步骤并保留非敏感草稿；密码不持久化，退出/完成后清除。验证码重发规则必须以服务端 challenge 为准。

主要第三方方式按平台和 provider 可用性选择：Apple 平台显示 Apple，Android 可用时显示 Google；GitHub、通行密钥和验证码登录在“其他方式”。用户历史偏好只能用于排序，不能把唯一可用的方式藏起来。正式按钮采用各提供商现有品牌组件；原型的外链图标只是授权流程示意。

“我的”继续负责四个本地设置入口；账户页专门管理身份、安全和权益，两者不重复堆设置。高级用户身份卡延续深色/金色细节和昵称旁徽章，不在卡内追加营销按钮。已购权益作为普通设置行仍可进入和恢复，不要求已购用户重复付款。

## 状态和文案

| 状态 | 处理 |
| --- | --- |
| 初始化/联网慢 | 明确加载或重试；不误显示游客/未购买 |
| 字段错误 | 输入框下方就地说明，保留输入，将焦点移动到错误字段 |
| 服务错误 | 当前任务内短提示与重试；不把技术堆栈当正文 |
| 发送/提交中 | 按钮内进度，防重复提交；完成前不切换步骤或退出，避免旧请求覆盖新页面 |
| OAuth 取消/超时 | 独立等待页退出或重试，保留设备码/扫码备用能力及 slow_down 处理 |
| 修改资料 | 有改动才启用保存；失败保留草稿；离开未保存内容提示，保存中阻止提前放弃 |
| 退出登录 | 明确本地书籍保留，账户权益按现有规则重新校验；不泛称所有商店版都永久免费 |
| 注销 | 保留已有预览→验证→最终确认、不能注销状态及权益影响说明 |
| 法律文档 | 复用现有协议/隐私入口和同意记录，不在登录页隐式引入新的同意语义 |

不为“专业感”添加假安全认证、盾牌勋章或“绝对安全”等承诺。不把登录宣传成自建云端书籍同步，WebDAV 仍是独立功能。

## 渠道与权益（独立商品规则）

- 商店账户页和设置卡提供无需登录的“应用解锁”入口，进入 `StoreReaderUnlockPage`，负责 14 天阅读试用、应用购买和恢复。永久解锁按 US$9.99 基准价配置。
- 商店版未获得永久阅读许可时，高级版入口、升级提示和高级身份徽章均隐藏；试用不能满足条件。直接打开高级页面时显示应用解锁页。
- 永久阅读许可生效后，高级版在单独页面按 US$8.99 基准价购买，并要求 Origo 登录。购买、验证、恢复文案与应用解锁分开。
- 官网自带永久阅读，无应用试用倒计时；高级版维持原有卡密兑换。商店页不显示卡密、官网支付或邀请销售入口。
- 价格取商店返回的本地化 `product.price`，不会用预览占位价格触发交易。真实商品未加载时给出加载/重试。
- 登录和退出只改变账号高级权益，不清除商店账号拥有的阅读购买。应用解锁不授予高级版，高级版也不自动授予应用解锁。
- 老客户按明确旧交易/迁移记录保留既有承诺。细节、接口和验证记录见 [独立商品方案](plans/2026-09-26-independent-store-products.md)。

## 视觉与适配验收

1. 每个普通手机设计状态主内容无多余纵向滚动；键盘/放大字号可以必要滚动。
2. 深色版登录与高级账户保持文字、字段和按钮层级；生产继续跟随用户选定的强调色。
3. 桌面/平板表单最大宽 440px，中心布局；不把字段拉满屏幕。列表可在宽屏居中限制宽度。
4. 点击目标至少 48px；验证码允许粘贴和系统自动填充，密码支持密码管理器、显隐语义和正确 autofill hints；注册禁用自动大写。
5. 动画仅使用正常页面进出和状态淡入，约 180–240ms，减少动态效果时关闭装饰过渡。
6. 生产接入保留原有 MFA、OAuth 回调、错误重试、取消、旧用户、渠道、购买/恢复和离线权限回归；Android/iOS 真机验证键盘、返回手势与外部授权回 App。

## 实施顺序与行为保护

1. 先运行既有账户、商店权益与安全测试，锁定现有行为。
2. 登录改为当前步骤表单，移除重复介绍/第三方区；保留 controller/API 与 provider 品牌组件。
3. 资料、安全、权益、邀请的呈现独立整理，保留原功能和渠道门控。
4. 新增注册分步/返回/错误恢复、provider面板及键盘布局回归，真实页面截图与静态分析通过后更新实施状态。
5. 本轮不上传或发布新商店包，不触碰并行欢迎页、阅读器等工作。

## 正式实现与维护入口

- `lib/pages/account/account_page.dart`：导航、认证阶段及外部授权生命周期。
- `parts/account_auth_form_part.dart` / `account_auth_part.dart`：表单校验、自动填充、provider 面板与身份卡。
- `parts/account_profile_part.dart` / `account_security_part.dart`：独立资料、安全页面。
- `parts/account_membership_part.dart` / `premium_membership_page.dart`：轻量入口、邀请二级页、购买与恢复前置。
- `test/account_page_test.dart`：注册分步、返回、验证码错误、重发、provider、小屏键盘、资料草稿与请求中返回。
- `test/account_security_redesign_test.dart`：小屏放大字号与邮箱验证方式切换。
- `test/account_authorization_cancellation_test.dart`：取消授权后的迟到响应、回调与重新授权。
- `tool/capture_account_production_test.dart`：真实生产组件渲染，输出 `docs/previews/account-redesign/implemented-*.png`，与早期原型分开。

实现细节：验证码重发冷却采用服务端错误的 `retryAfter`，成功发送后不虚构 API 未返回的冷却时间。Provider 按平台与可用性排序，未增加历史偏好存储。帮助仍位于“我的 → 关于与支持”，账户页不重复增加入口。

正式截图已检查登录、密码、注册详情、深色登录、高级账户、安全概览；390×844 注册详情滚动范围为 0。键盘弹出时滚动区域位于共享顶栏下方，按钮不会被浮动返回栏挡住。Android/iOS 真机键盘、平台外部授权和真实付款仍需设备验收，截图测试不替代这些环节。

正式回归记录：账户服务 53 项、授权取消 2 项、安全界面 1 项通过；权益行为 20 项通过，另 4 个按需截图测试显式开启后通过。权益截图存放于 `production-membership/`，截图价格来自测试商店数据，不是当前线上售价。授权取消会等待旧请求和令牌清理结束再开放新登录，清理期间显示忙碌，避免迟到响应覆盖新会话。

最终账户界面验证：14 项常规回归和 2 项慢请求回归通过，包含登录期间字段禁用、资料保存期间顶栏/系统返回拦截。正式截图测试通过；代码、测试和截图入口静态分析无问题，差异空白检查通过。最终 `flutter build apk --debug --no-pub --target-platform android-arm64` 构建通过（229.4 秒）。构建仍提示现有 Kotlin Gradle Plugin 的未来兼容性迁移警告，本轮未升级依赖。未安装覆盖用户当前测试包、未发布。
