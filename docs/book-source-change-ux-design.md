# 换源交互与 UI 设计（方案草案）

日期：2026-09-24。范围：已绑定在线书的换源、未绑定本地书的绑定入口，以及从阅读器和书库进入时的返回路径。本文件保留完整交互与发布验收目标；用户反馈的“卡住”尚无可复现日志，下面列出的风险是从原代码推断，不作为已确认的故障原因。

## 当前实现状态

已落地双视图、增量候选与停止搜索、分阶段检查和取消、章节映射确认、阅读位置持久化及阅读器打开后的成功提示。当前测试覆盖迟到验证结果、位置不可用时的手动选择、事务回滚和迁移等场景。下方目标表仍是发布门槛，不能将自动化测试通过等同于真机性能达标；设备 p95/p99、弱网、3,000 书源帧时间及长时间资源曲线仍需按表实测。

当前保留旧书签和笔记记录，并在在线换源时清除书架行中旧正文的 canonical/rendered 定位缓存；跨来源书签和笔记的原文锚点尚无来源版本字段，不能承诺自动精确定位。相关交互和迁移需单独补齐后才能宣称这一项通过发布验收。

## 现状与问题

- `BookSourceChangePage` 进入后自动搜索，首轮最多检查 60 个书源、收集 8 个候选；点候选时先等待旧阅读位置，再顺序读取新书详情、目录和映射章节正文。页面只显示“正在验证目录和当前章节…”，没有阶段、耗时、取消或重试。`validate` 与 `loadPosition` 没有整体超时，搜索的 6 秒计时器依赖底层请求响应取消信号。
- 搜索的“已检查 n / 总书源数”与首轮只查 60 个、达到 8 个结果后提前停止的语义不同。结果会在搜索过程中重排，用户准备点的候选可能移动。
- 提交后当前页面先退出；阅读器入口还要再打开新阅读器。需要把“书架关联已更新”与“新来源已打开”分别表述，避免后一步失败时给出完整成功的错觉。
- 在线书、已下载的本地书共用入口，但保留本地正文和阅读位置的含义不同；界面须在确认前说明。现有 `replaceOnlineSourceBinding` 对本地书保留文件与阅读进度，对在线书按新目录重映射进度。

## 目标与边界

1. 用户始终知道正在查什么、已找到什么、下一步会更改什么，以及能否安全返回。
2. 坏书源或慢网络不能让页面永久转圈；超时可重试、换候选或取消。
3. 用户确认前不改书架关联；搜索、预览或验证失败保留原来源。
4. 优先复用 `FloatingSubpageScaffold`、`bookSourcePanelDecoration`、现有主题色、书源卡片和底部主按钮，不增加新的设计系统或依赖。

本期不设计自动换源、后台扫描全量书源、登录失效自动修复或跨书源书签语义迁移。候选匹配只说明“同书名 / 同作者”，不承诺内容完全相同。

## 信息架构

单个“换源”子页面内采用两个明确视图，避免搜索列表和验证详情同时争夺空间：

1. **找来源**：当前书的紧凑摘要、搜索与筛选、稳定的候选列表、搜索状态。
2. **确认切换**：选中候选、详情/目录/正文检查状态、原章节到新章节的映射、数据影响说明、确认按钮。

从阅读器或书库进入沿用现有入口。返回键从确认视图回到结果；从结果页返回原阅读器或书库。两处都不修改来源。确认切换后保持入口语境：书库回到该书条目，阅读器打开新来源的映射章节。

## 交互状态机

```text
进入 → 加载书源 → 搜索中 ──→ 有候选/搜索结束
                    │               │
                    └─取消/超时──────┤
                                    ↓
                             选择候选 → 检查中
                                      ├─失败/超时 → 重试 / 返回列表
                                      └─通过 → 确认切换
                                               ├─取消 → 原来源不变
                                               └─提交中 → 已写入关联
                                                            ├─阅读器成功打开 → 完成
                                                            └─打开失败 → 已切换，提供重试打开
```

### 找来源

- 进入后用当前书名自动搜索；默认校验作者。首轮仍用有界搜索，但进度写成“快速查找：已检查 24 / 60”，旁边说明总计有多少可用书源。提前找到足够候选时写“已找到 8 个，暂停查找”，不写“全部完成”。
- 候选出现即可选择。正在搜索时保持已显示行的位置；新候选追加到列表，待搜索暂停/结束或用户主动选择“按匹配度排序”时再排序。已选候选在返回列表后保持可见。
- 状态行提供“停止查找”；停止仅结束当前任务，保留结果。首轮结束后提供“继续查找其余来源”。修改书名、作者校验或重新搜索时，明确开始新一轮并清除旧结果，避免旧候选看似属于新关键词。
- “没有找到”和“有书源请求失败”分开展示：前者给“修改书名 / 关闭作者校验”，后者给“重试失败书源”；没有可用书源时给“管理书源”入口。

### 检查候选

- 点击候选进入确认视图，按“读取原阅读位置 → 获取书籍详情 → 获取目录 → 检查映射章节正文”显示当前步骤；已完成步骤使用勾号，未开始步骤保持静态。显示已耗时，不伪造百分比。
- 搜索可在候选检查时暂停；仍有结果时返回列表可继续。检查目标书源失败不清空其他候选。
- 读到的原章节标题与目标章节标题并列，标记“按章节标题匹配”或“按章节位置估算”。仅在正文成功返回且非空时显示“当前章节可读”。若作者不一致，展示明显的人工确认提示。
- 点选后立即显示选中反馈；超过 1 秒显示正在执行的具体步骤，超过 3 秒提示“这个来源响应较慢”，始终有“取消检查”。达到整体上限后进入“检查超时”，可重试或换来源。实现须让底层请求按取消/超时终止，而非仅隐藏转圈。建议 20 秒作为单次检查整体上限，最终值经真实书源样本验证。
- 如果旧来源目录不可用，显示“原目录读取失败；将按已保存的章节位置估算”，并在确认视图标明映射不确定性。不能把估算结果标成精确匹配。

### 确认与提交

- 主按钮仅在验证成功后可用，文案为“确认换到〈书源名〉”。按钮上方说明“已确认新来源当前章节可读；换源后继续从第 N 章阅读”。章节定位显示证据等级：标题匹配、章节号匹配、按位置估算；后两者不能伪称精确，估算时让用户预览并选择目标章节。不同来源的章内百分比不等于同一段文字，不能静默当作精准位置迁移。
- 在线书说明：更新书架关联与阅读位置；原来源仍在书源管理中。已下载书说明：只更改续更来源，本地正文与现有阅读位置保留，后续章节映射可能需要再确认。无书架记录时仅切换当前阅读会话。
- 提交前检查目标版本是否已单独在书架；冲突时保持原绑定并给出“查看书架中的版本 / 选择其他来源”。提交按钮防重复点击。提交中显示“正在保存来源”，按钮不可再次触发；本地提交异常时回到确认视图并明确“未完成切换”。
- 阅读器入口提交成功后继续显示“来源已保存，正在打开阅读”。只有新阅读器显示可读内容才提示“换源完成”；打开失败时说明“来源已切换，但未能打开正文”，提供“重试打开 / 返回书架”，不暗示回滚。书库入口在关联写入并刷新书卡后显示完成。

## 平板、桌面与无障碍

- 宽屏最大内容宽度沿用现有 760px；不另做多栏页面。可在宽于 900px 时把结果列表和候选检查并列，但必须保持相同状态机和按钮位置。
- 触控目标至少 44×44；桌面支持 Tab、Enter、Escape，返回焦点落回刚才的候选。候选状态不可只靠颜色，读屏播报“正在检查 / 已通过 / 失败”。进度播报节流，不为每个书源刷屏。
- 文字放大时书名、书源名允许两行；作者警示、映射信息和操作不截断。尊重减少动态效果设置，检查状态不使用无限旋转作为唯一提示。

## 失败与文案矩阵

| 阶段 | 用户可见文案 | 可操作项 | 数据结果 |
| --- | --- | --- | --- |
| 搜索慢/部分失败 | `已检查 24 / 60；3 个来源暂时无法响应` | 停止、重试失败来源、继续其余 | 原来源不变 |
| 原目录慢/不可用 | `原目录暂时不可用，将按已保存位置估算` | 继续检查、返回 | 原来源不变 |
| 新目录为空 | `这个来源没有可用目录` | 重试、换来源 | 原来源不变 |
| 正文为空/网络超时 | `当前章节未能读取` / `检查超时` | 重试、换来源 | 原来源不变 |
| 目标已在书架 | `这个版本已在书架中` | 查看书架、换来源 | 原来源不变 |
| 保存失败 | `未完成切换，请重试` | 重试保存、返回 | 原来源不变；由存储层保证 |
| 保存后打开失败 | `来源已切换，但正文暂时无法打开` | 重试打开、返回书架 | 新关联已生效，明确告知 |

技术错误详情可复制，但默认文案不直接显示异常类名或堆栈。

## 数据正确性契约

“换源成功”的数据条件：书架绑定、新来源阅读位置及必要的续更状态已一致地持久化；返回的新阅读器实际呈现可读章节，才称“阅读已接续”。本地文件、原来源进度、书签、笔记和阅读统计不能因换源丢失。此处是下一轮实现目标，不表示现有代码已经满足。

| 数据 | 当前事实 | 目标行为 |
| --- | --- | --- |
| 书架身份与来源 | `BookDao.updateSourceBinding` 在 SQLite 事务里条件更新；书架 `id` 保持不变 | 用同一书架身份切换绑定；提交前复核原绑定，目标版本重复时拒绝；并发阅读与自定义封面更新不可被旧快照覆盖 |
| 在线阅读位置 | 新来源的章节位置先写 `SharedPreferences`，后更新 SQLite 书架行 | 迁到已有 SQLite 数据库的阅读位置表；书架绑定、目标章节 ID/索引/进度在一次事务内写入；旧位置仍可按旧来源读取，供恢复或返回 |
| 未入书架的在线书 | 位置也在 `SharedPreferences` | 用同一 SQLite 位置表按来源 ID + 书籍 ID 保存；迁移旧值时幂等、保留时间较新的记录，避免读新旧两套真相 |
| 本地下载书 | 换源更新续更绑定，保留现有 TXT 文件与书架进度；章节边界另有侧车状态 | 原文、内容哈希、阅读位置和用户编辑历史不变；新来源先进入“待确认章节对应”状态，不自动写入本地正文 |
| 封面 | `replaceOnlineSourceBinding` 在数据库更新前等待 `_storedCoverPath`，可能触发网络下载/生成 | 封面作为非关键后续任务；先完成绑定，旧封面或占位图继续可用。后续更新须核对书架行仍指向同一新来源，不能由旧任务覆盖新封面 |
| 书签、笔记 | 记录跟随书架 `bookId` 保留，但章节 ID、锚点和偏移可能属于旧来源 | 永不删除；记录来源版本，旧锚点在新来源没有验证前标为“原来源位置”，不按相同索引和偏移静默跳到错误正文；可逐条重新定位 |
| 阅读统计、用户标题 | 阅读统计跟随书架身份；当前绑定更新仅改来源字段 | 统计和用户编辑的书名/作者、书架顺序保持原样，不重复创建同一本书 |
| 正文/目录缓存 | 由来源和书籍请求产生 | 以来源 ID + 书籍 ID + 章节 ID 隔离；新来源不复用旧正文。候选预检已读到的章节可在同一会话短时复用，减少确认后再次联网 |

`SharedPreferences` 官方说明明确不保证 `setString` 返回时已落盘，也不建议存储关键数据；因此只加 `Future.timeout` 或补偿删除，不能解决“进度已写而绑定未写”的跨存储事务问题。目标是让 SQLite 成为换源关键状态的唯一写入点，沿用现有数据库依赖，不增加新依赖。旧版进度迁移需覆盖升级、重复启动、崩溃中断、跨来源重名书、旧值较新等情况。参考：[shared_preferences 官方说明](https://pub.dev/packages/shared_preferences)、[SQLite 事务说明](https://www.sqlite.org/lang_transaction.html)。

目标书是否已存在不能只在事务前查一次；提交事务内要重新核对，或在清理历史重复数据后加数据库唯一约束。若用户在搜索期间继续阅读，提交时也要对比最新位置并重新映射或要求用户确认，不能用进入页面时的旧进度覆盖较新的阅读进度。

本地下载书还涉及数据库外的侧车文件：先准备可恢复的变更意图，再提交数据库；提交后更新侧车，应用下次启动能按意图补全。不能把跨 SQLite 与文件系统的多步写入称为单一原子事务。取消发生在提交点之前时无新关联；提交点之后若发生异常，界面明确报告“已保存来源，后续处理待恢复”，并由幂等恢复任务完成。封面和缓存失败不改变提交结果。

章节映射接口应返回 `{目标章节, 证据等级, 原位置摘要}`，不只返回整数索引。标题/章节号匹配也要验证目标正文；比例估算需要人工预览。章内位置优先用可核验的文本锚点；无法核验时默认从映射章节开头进入，并让用户看到原位置摘要与手动调整入口。原来源位置保留，避免不可逆的“精准续读”假象。

## 性能与流畅度验收

下表是本功能拟定的**发布门槛**，不是第三方统一规定的绝对耗时。外部书源响应时间单独统计，不把坏网络算作界面掉帧，也不以快网络掩盖主线程卡顿。

| 指标 | 目标 | 测量方法 |
| --- | --- | --- |
| 点按反馈 | 选候选、取消、返回、确认的视觉反馈 p95 ≤ 100 ms | 真机触摸事件到首个状态帧；每种操作至少 100 次重复测量 |
| 页面可操作 | 进入后搜索框、返回键与状态占位 p95 ≤ 300 ms；书源总量 3,000 时仍可操作 | 冷/热启动分别测；不等待书源解析或网络完成才画首屏 |
| 结果呈现 | 搜索事件到候选可见 p95 ≤ 200 ms | 注入可控延迟的假书源，单独排除远端 RTT |
| 滚动与状态帧 | 60 Hz 设备 99% 帧在 16.7 ms 内；120 Hz 设备以 8.3 ms 为目标；零长时间冻结帧 | Flutter profile 模式、DevTools 帧图、真实低中档设备；搜索流入和滚动同时发生 |
| 取消与超时 | 用户点取消后 p95 ≤ 300 ms 返回可操作状态；请求尽快释放；候选检查整体最多 20 秒后给出结果或可恢复错误 | 网络永不返回、DNS 慢、正文很大、快速重复切换目标的故障注入 |
| 内存与资源 | 反复搜索/返回 20 轮后无持续增长的订阅、计时器、请求和候选缓存；正文不为搜索批量下载 | DevTools 内存快照、连接数和主动任务数对照基线 |
| 数据可靠性 | 取消/失败不改当前绑定；提交后重启仍保有新绑定与正确位置；重复提交不产生重复书架项 | 事务故障注入、强杀重启、并发阅读/换源、迁移回归 |

搜索沿用优先级与有界首轮，但调度须限制全局并发和同站点并发，避免导入大量同域书源时瞬间淹没站点或设备；先用当前 12 个并发建立基线，再依据真实源的吞吐与失败率调整，不凭直觉固定更大的线程数。候选列表增量追加，批量刷新和局部重建；可见行位置不因迟到结果跳动。大型书源 JSON 已有后台解析路径，只有 profile 证明仍有超过帧预算的计算时才继续移到 isolate。Flutter 官方建议在 profile 模式测量帧，并在大量计算导致卡顿时使用 isolate；不应把网络等待误判为 UI 线程冻结。参考：[Flutter 性能指南](https://docs.flutter.dev/perf/best-practices)、[Flutter isolate 指南](https://docs.flutter.dev/perf/isolates)、[Flutter 集成测试性能测量](https://docs.flutter.dev/cookbook/testing/integration/profiling)。

交互反馈按约 0.1 秒、1 秒、10 秒三个感知尺度设计：即时状态回应；超过 1 秒显示明确阶段；长于 10 秒必须能看到真实进度与中断入口。本文的 3 秒慢提示、20 秒检查截止是产品提议，需真实样本校准。参考：[Nielsen Norman Group 响应时间指导](https://www.nngroup.com/articles/response-times-3-important-limits/)。Dart 的 `Future.timeout` 只让等待方超时，原请求仍可能继续；必须把取消信号传到 HTTP/规则执行层，并用任务代际防止迟到结果写入。参考：[Dart Future.timeout API](https://api.dart.dev/dart-async/Future/timeout.html)。

性能验收数据按阶段记录 `registry_load / search / position / detail / catalog / content / commit / reader_open` 的持续时间、结果类别和并发数；关联一次换源任务的匿名 ID。默认本地诊断不记录书名、正文、登录凭据或完整书源 URL；导出日志需用户主动操作。报告 p50/p95 与失败率；样本数足够时再报告 p99。按平台、书源规模、网络条件区分，避免仅用平均值或单台开发机作为“顺畅”的证明。

## 实现契约与验收

- 统一一次换源任务的所有异步阶段：任务 ID / generation、可取消请求、每阶段超时、整体截止时间。超时或取消后旧回调不能覆盖当前界面；网络调用真正释放资源。若底层协议暂不支持取消，先补齐服务接口再交付“取消检查”交互。交付以本文件的数据正确性契约和性能发布门槛为准。
- 位置加载失败必须进入可解释的降级状态，不能让选中候选永远等待。搜索中的单个书源异常不阻塞其他书源或结束事件。
- 保留现有的正文可读验证、目标已在书架冲突检查、提交前不改关联、在线/本地书的不同位置处理。确认视图使用服务返回的实际匹配依据，不根据章节标题字符串自行猜测。
- 提交写入需要明确事务边界：若关联未写入，原绑定可继续阅读；若已写入而后续打开失败，不自动宣布回滚。封面获取等非关键请求不得阻塞确认结果。
- 验收场景：搜索 60 源中有超时源；旧目录永不返回；候选详情/目录/正文任一步永不返回；检查时返回并选另一个候选；快速重复点击确认；作者不匹配；章节标题匹配和位置估算；本地下载书绑定；目标书已在书架；保存失败；保存成功但阅读器打开失败。每个场景均能在有界时间内退出等待，并核对真实书架关联及阅读位置。另测旧书签/笔记定位、进度迁移、侧车恢复、书源总量 3,000 时的真实帧时间。
